## 1. Frames that are directly usable (with exact file/section)

### 1.1 The four-stage chain — the brief's organising spine
**Source:** `council/debates/D015_transparency_reconciliation.md`, "## Verdict" (line 81): *"The four-stage chain (detect → identify → custody → effect) … is confirmed as the correct universal decomposition — every case on the table … resolves cleanly into 'which link broke, or held.'"* Origin brief: `sweeps/codex_round3b_batch/01_transparency_question.md` §"Question and measurement discipline" (the chain is stated as a code block there).
**Stamp after D022:** core reconciliation **Med-High · elicited** (D022 downgrade table, row D015); the identify-stage recurrence claim **High · documentary** (held).
**How it maps onto FIRMS:**
- *Detect* = a VIIRS 375 m pixel exceeds the thermal threshold on one of ~2 overpasses/day. The feasibility pass measured this gate directly: front-band density 5–17× rear in every month (`out/monthly_front_vs_rear.csv`: Jul-2025 307 vs 20 per 1,000 km²), but 44% of sector-weeks have zero front detections and Nov–Feb front density is 0.2–1.7 per 1,000 km²/month. **That is a Gate-1 physics result in D015's vocabulary** — fuel, snow, cloud and overpass cadence close the detect link for ~4 months/year, symmetrically for both sides.
- *Identify* = is this vegetation fire combat or agriculture? The `type` field (0/2/3), day/night flag, FRP and the pre-war 2019–21 per-pixel baseline are the identify tools. FIRST_PASS "What contaminates the signal" is already an identify-stage failure catalogue.
- *Custody* = can a sequence of detections be held as a track through a sector-week? Twice-daily snapshots and cloud gaps break custody; this is why "no detection ≠ no fire."
- *Effect* = does a detection convert into an analyst-useful call (here: territorial change)? FIRST_PASS §5: fires add R² 0.464→0.469; lead-lag curve flat from −4 to +4 weeks. **The feasibility null is an "effect-link" null, not a "detect-link" null** — the brief can say exactly where the chain breaks, which is the D015 move.
**Use:** structure the brief's §1–§3 as the four links, with a measured number per link. This converts "we found almost nothing" into "we located where a free sensor's chain breaks."

### 1.2 Force-to-space density regimes — why fires can locate fighting but not forecast it

## 3. Census variables that are usable — and how

The census (`census/conflict_list.json`, 412 rows; schema `02_typology_matrix.md`) is **not** a data source for this project (see §5). But four of its *variable definitions* are usable as coding templates for the project's own small case set:

1. **`force_space_density.regime`** (`02_typology_matrix.md` "Force-to-space density" rule; D008 mechanical test). Use it to code each **sector-phase** of Ukraine 2022–25 and each Sudan theatre, by the written test, *before* looking at fire results. This is the project's main stratification variable and is `definitional` basis.
2. **`reconnaissance_strike_symmetry`** (`02_typology_matrix.md`, with the D019-SCOPE-3 quarantine block — do **not** read the interaction rule before coding). Use the sustainment-anchored definition from D019 SCOPE-3 (line 194): *"documented evidence of sustained resupply or domestic production of reconnaissance and strike systems on both sides, plus at least one sourced capability revision by each side."* Code it for Ukraine 2022 vs 2024–25 and SAF vs RSF.
3. **`terrain`** 9-value enum (with B4's fold table, `sweeps/claude_wave9/analysis/B4_transparency_fork.md` §1) — useful for the blind-spot product: FIRMS performance should be tabulated against terrain class (steppe/cropland vs forest vs desert vs urban). B4's own finding (jungle almost never saturated-linear; open maritime 88% engagement-point) is a reminder that terrain and regime co-vary weakly (Cramér's V 0.165, High · mechanical).
4. **The two-axis stamp and `basis` field** (D022) — as a column in every output table.

**Do not use:** census row counts as base rates; `prewar_favorite_won` or `outcome` as outcome proxies (D019 §(a): they measure political outcome, not tactical form); any `confidence: High` on a census row (236/239 fail Rule 3).

## 7. Hypotheses from the corpus that the fire data can actually test

Each is stated as a pre-registrable prediction with the corpus mechanism it comes from, the data needed, and what a null means. Numbers in brackets are from `frontline/out/`.

**H1 — The D008 regime hypothesis (within-war, Ukraine).** *Fires lead territorial change only in non-saturated-linear phases.* Prediction: in sector-weeks coded `porous-linear` or collapse/manoeuvre (Kharkiv Sep–Oct 2022, Kherson Oct–Nov 2022, Kursk Aug 2024–Mar 2025 using the Russian-Federation FIRMS file), the lead-lag curve shows a positive peak at +1 to +2 weeks and the fire coefficient survives momentum; in `saturated-linear` 2024–25 it does not [current: flat −4…+4, coeff 0.85, p 0.048, R² gain 0.005]. Data: DeepState API history back to 2022-04-03 (~1,800 snapshots, ~200 KB–1 MB each); FIRMS 2022–23 country CSVs (already have 2023); regime coded per sector-phase by D008's written test *before* analysis. Null meaning: fires never lead, in any regime → the method is a locator only, period. Mechanism: D008 verdict line 90; D011 line 58. **Stamp of the mechanism: Med · elicited (D011) / High · documentary (D008).**

**H2 — The D011 symmetry hypothesis (the Kursk test).** *Where one side selected a weak-ISR sector (asymmetric), the thermal signature of the advance arrives with or after the territorial change, not before — because surprise means low pre-attack fires.* This is the sharper, falsifiable version of H1 for a single named event.
